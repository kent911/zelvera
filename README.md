# Zelvera — локальный медицинский ИИ-ассистент

**Языки:** Русский · [English](README.en.md)

Полнофункциональное локальное приложение: чат с ИИ, распознавание анализов
(фото/PDF/DOCX), личная медицинская карта, база научных статей с RAG-поиском,
заметки, профили здоровья и напоминания. Данные остаются локальными.
Ассистент не ставит диагнозы и не заменяет врача.

## Стек

- Backend: Python 3.11+ / FastAPI + Uvicorn
- ИИ: Ollama (локально, по умолчанию) либо любой OpenAI-совместимый API
- Frontend: HTML/CSS/JS без сборщика (оборачивается в десктоп через pywebview)
- Хранилище: SQLite (мед. карта, заметки, аудит, профили) + ChromaDB (статьи)

## Запуск

### 1. Локальная модель (Ollama)

```bash
# установите Ollama: https://ollama.com
ollama pull gemma4:26b
ollama serve
```

Модели по умолчанию (настраиваются в `backend/.env`):
- чат и vision-распознавание фото: `gemma4:26b`
- эмбеддинги для статей: `nomic-embed-text` (`ollama pull nomic-embed-text`)

Модель держится в памяти Ollama 30 минут (`OLLAMA_KEEP_ALIVE`, по умолчанию
`30m`), иначе первый запрос после простоя платит за холодную загрузку
(~20 c для 26b).

### 2. Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

### 3. Старт

```bash
python run.py
```

Откройте http://127.0.0.1:8000 в браузере.

`run.py` слушает `0.0.0.0:8000` и **не** включает автоперезагрузку — это
безопасный режим для сервиса (перезагрузка во время ответа бота теряет
сообщение). Для разработки включите её: `ZELVERA_DEV=1 python run.py`.
Адрес и порт задаются переменными `ZELVERA_HOST` и `ZELVERA_PORT`.

## Десктопное окно (Шаг 6, pywebview)

```bash
cd backend
pip install -r requirements-desktop.txt
cd ..
python desktop.py
```

Запускает локальный сервер в фоновом потоке и открывает нативное окно.
Если GUI-бэкенд недоступен — открывает приложение в браузере (fallback).

Требования платформы для окна:

- **Windows**: Microsoft Edge WebView2 (предустановлен в Win10/11).
- **macOS**: `pip install pyobjc`.
- **Linux (Debian/Ubuntu)**:
  ```bash
  sudo apt install libgirepository1.0-dev gir1.2-gtk-3.0 gir1.2-webkit2-4.1 python3-gi
  ```

## Сборка Windows (.exe) и CI

Один исполняемый файл для Windows собирается через PyInstaller (`zelvera.spec`).

```bat
build_windows.bat
```

Скрипт проверяет наличие Python 3.11+, устанавливает зависимости из
`backend\requirements-desktop.txt` и собирает приложение в `dist\Zelvera\`.

GitHub Actions (`.github/workflows/build-windows.yml`) повторяет ту же сборку
на `windows-latest`, проверяет наличие `Zelvera.exe` и загружает
артефакт `Zelvera-windows` — запускается на push/PR или вручную
(workflow_dispatch).

Отдельный workflow `.github/workflows/tests.yml` на `ubuntu-latest` запускает
`pytest` (папка `backend/tests`): каталог маркеров, справочник норм, кеш и
grounding справки Википедии, извлечение маркеров. Локально:

```bash
cd backend
pip install -r requirements-dev.txt
python -m pytest -q
```

## Резервное копирование

В настройках («Настройки Ollama») есть блок «Резервная копия»:

- **Сохранить копию** — скачивает ZIP-архив со всеми данными: `medical.db`
  (мед. карта, статьи, заметки, профиль, напоминания, аудит), `settings.json`
  и векторная база статей `chroma/`;
- **Восстановить из копии** — загружает ZIP-архив; данные полностью
  заменяются (с подтверждением). Архив проверяется на целостность и наличие
  `medical.db`;
- все действия фиксируются в журнале аудита (`backup_export`, `backup_import`).

## Шаг 2 — обработка документов

Кнопки «Фото анализов» и «Документ (PDF/DOCX)» в чате:

- **Изображения**: vision-модель распознаёт текст бланка (OCR).
- **PDF/DOCX**: текст извлекается локально (PyMuPDF / python-docx), таблицы бланков читаются построчно.
- Затем LLM извлекает маркеры здоровья в JSON: `{name, value, unit, reference_range, status}`.
- Результат показывается таблицей в UI; кнопка «Спросить ИИ» отправляет разбор в чат.
- В промпт передаётся каталог известных показателей (канонические имена и
  синонимы/аббревиатуры, сгруппированные по категориям) — модель сопоставляет
  `HGB`, `WBC`, `ALT` с каноническими названиями сразу. Если показателя в
  каталоге нет, имя сохраняется как в бланке (без подмены похожим).
- Если название показателя не найдено в каталоге (новый/непонятный/искажённый
  маркер), приложение ищет справку в офлайн-Википедии (Kiwix) и повторно
  уточняет разбор; под таблицей появляется блок «Уточнено по Википедии» со
  ссылками на статьи. Если Kiwix недоступен — сохраняется исходный разбор.

Для распознавания фото нужна vision-модель в Ollama:

```bash
ollama pull gemma4:26b   # поддерживает изображения
```

## Шаг 3 — личная медицинская карта (SQLite)

Распознанные маркеры автоматически сохраняются в `data/medical.db` (исключён из git):

- Таблица `records` — дата, источник, резюме.
- Таблица `markers` — название, значение, единица, референс, отклонение.

Во вкладке «Моя мед. карта» отображается история анализов: дата, источник,
число показателей, резюме. Записи разворачиваются в таблицу маркеров
и удаляются кнопкой «Удалить».

Кнопка «Динамика» показывает графики по каждому показателю с коридором нормы
(пунктирные границы и подсвеченная полоса), датами и точками значений.
Кнопка «Сравнить» открывает панель: выберите два анализа (раньше/позже) и
получите таблицу изменений — рост, снижение, появление/исчезновение
показателя и смену отклонения.

Кнопка «Отчёт за годы» собирает все анализы за выбранный период (например,
2018-2025; годы вводятся вручную, по умолчанию — самый ранний и поздний из
записей) в таблицу «показатель × год»: медиана, число измерений и оценка
строки (стойко выше/ниже нормы, улучшение, ухудшение, колебания). Кнопка
«Сформировать отчёт ИИ» строит общий текст о здоровье за период по этой
сводке; отчёт носит ознакомительный характер и не заменяет врача.

### Критические отклонения (алярмы)

Для части показателей заданы критические пороги (например, гемоглобин ниже
70 г/л, глюкоза выше 27,8 ммоль/л, тромбоциты ниже 20, калий ниже/выше
2,5/6,5 ммоль/л и т.п.):

- в таблице маркеров критические значения подсвечиваются пульсирующим
  красным значком «⚠ Критично!»;
- в списке записей появляется бейдж «⚠ N критич.»;
- инструмент ИИ `get_medical_card` в начале ответа выводит блок
  «ВНИМАНИЕ: обнаружены КРИТИЧЕСКИЕ отклонения, требующие срочного
  внимания врача»;
- база порогов и синонимов — в `backend/app/services/critical.py`,
  а канонические имена и синонимы показателей — в
  `backend/app/services/marker_catalog.py`.

## Каталог показателей и справка из Википедии

Единый каталог показателей (`backend/app/services/marker_catalog.py`) содержит
51 показатель, 16 категорий и 242 синонима (русские/английские названия и
аббревиатуры). Он используется везде, где показатель нужно сопоставить:

- нормализация имён при записи в мед. карту («Hb», «HGB» и «Гемоглобин» — одно);
- промпт распознавания документов — модель сразу приводит синонимы и
  аббревиатуры из бланка к каноническим именам;
- группировка динамики в трендах и подписи в алярмах/напоминаниях;
- API `GET /api/markers/catalog` — полный список для интерфейса.

Если показатель отсутствует в каталоге, приложение обращается к офлайн-Википедии
через Kiwix и кеширует найденную справку в таблице `wiki_cache` (SQLite) на
7 дней — включая отрицательный результат «не найдено», чтобы не повторять
поиск. Справка используется:

- при разборе документов (дополнительный проход LLM + блок источников в UI);
- в чат-инструментах `get_medical_card`, `get_marker_trends` и
  `check_marker_norm` — модели добавляется справка по незнакомым показателям.

Любые сбои Kiwix, сети или таймаут не влияют на основной ответ: справка просто
не добавляется.

## Меню настроек Ollama

Кнопка «Настройки Ollama» в боковом меню:

- поле адреса Ollama;
- «Обновить список моделей» — запрашивает модели у запущенной Ollama (`/api/tags`);
- выбор чат-модели, vision-модели и эмбеддинг-модели (можно вводить вручную);
- сохранение переживает перезапуск (`data/settings.json`); приоритет над `.env`.

## Шаг 4 — база научных статей (ChromaDB / RAG)

Во вкладке «База статей»:

- Загрузка PDF/DOCX/TXT → текст извлекается, делится на перекрывающиеся чанки,
  для каждого чанка считаются эмбеддинги (Ollama `nomic-embed-text`
  или OpenAI `text-embedding-3-small`), LLM пишет резюме на русском.
- Чанки хранятся в ChromaDB (`data/chroma`, косинусная метрика), метаданные
  статьи — в SQLite.
- Поиск по смыслу: запрос эмбеддится и ищется по всем чанкам, возвращаются
  релевантные фрагменты с «близостью». Каждый фрагмент можно обсудить с ИИ.

Требуемые локальные модели Ollama:

```bash
ollama pull nomic-embed-text
```

## Шаг 5 — аналитический отчёт «анализы ↔ статьи»

Кнопка «Аналитический отчёт» в чате:

1. Берёт актуальные показатели из мед. карты (по последним значениям каждого маркера).
2. Эмбеддит их и находит в ChromaDB релевантные научные фрагменты.
3. LLM составляет персонализированный отчёт: обзор показателей → сопоставление
   с научными данными → что отслеживать → дисклеймер.

Ассистент не ставит диагнозы и не назначает лечение; каждый отчёт завершается
дисклеймером о необходимости консультации врача.

## Заметки — выводы ИИ по статьям

ИИ в чате — языковая модель, он не пишет в базу сам. Сохранение делает
интерфейс:

- В чате нажмите «Сохранить вывод» — откроется окно с последним ответом ИИ,
  выберите статью (необязательно) и сохраните в базу.
- Вкладка «Заметки» в боковом меню — все сохранённые выводы с датой
  и привязкой к статье, можно удалить.
- Вкладка привязывается к статье автоматически, если диалог начат кнопкой
  «Обсудить с ИИ» или «Спросить ИИ об этом фрагменте».

## Инструменты ИИ (function calling)

Чат поддерживает вызов инструментов (только чтение, без записи в базу):

- `search_articles(query, limit)` — смысловой поиск по базе научных статей;
- `list_articles()` — список загруженных статей;
- `get_medical_card(days)` — актуальные показатели из медицинской карты
  текущего профиля (опционально — за последние N дней);
- `get_profile()` — анкетные данные профиля: имя, год рождения и возраст,
  группа крови, рост, вес (также подмешиваются в системный контекст чата);
- `get_marker_trends(marker, days)` — динамика показателей по датам,
  число измерений и направление тренда;
- `check_marker_norm(marker, value, unit, sex, age)` — проверка значения по
  справочнику референсных норм (с учётом пола и возраста);
- `save_analysis_to_card(markers, date)` — сохранение обсуждённых показателей
  в мед. карту одной записью;
- `search_wikipedia(query, limit)` и `list_kiwix_books()` — поиск в
  офлайн-Википедии (Kiwix);
- `search_memory(query)` / `list_memory()` — факты долгой памяти профиля;
- `save_memory_fact(category, key, value)` — запомнить факт по явной просьбе
  пользователя (не цифры анализов).

Инструменты чтения карты (`get_medical_card`, `get_marker_trends`,
`check_marker_norm`) автоматически добавляют справку из Википедии по
показателям, которых нет в каталоге (см. раздел выше).

Инструменты работают с единственным профилем здоровья: отредактируйте профиль
в шапке (кнопка-карандаш) — ИИ будет отвечать по данным этого профиля.

Поддерживается обоими бэкендами: Ollama (`tools`) и OpenAI-совместимым API
(`tools`). Если модель не поддерживает инструменты или они недоступны —
чат автоматически переходит к обычному ответу без инструментов.

## Долгая память ассистента (L0–L3)

Локальный аналог иерархической памяти агента. Всё в `data/medical.db`,
без облака:

- **L0** — сырые реплики диалога (`memory_messages`);
- **L1** — устойчивые факты: аллергии, привычки, жалобы, лекарства
  (`memory_facts`); разовые цифры анализов сюда не пишутся — они в мед. карте;
- **L2** — сжатые итоги недавних диалогов (`memory_summaries`);
- **L3** — короткий портрет профиля (`memory_profile`).

После ответа чата (веб и Telegram) факты извлекаются в фоне. Релевантные
L1–L3 подмешиваются в системный контекст следующего вопроса. Вкладка
«Память» показывает факты и портрет, их можно править вручную.

## Аудит действий

Вкладка «Аудит действий» в окне «Логи и ошибки» показывает историю действий
пользователя (SQLite, таблица `audit_log`):

- запросы в чате и аналитический отчёт;
- распознавание документов (фото/PDF/DOCX) и добавление записей в карту;
- загрузка/удаление статей и поиск по ним;
- сохранение/удаление/экспорт заметок;
- редактирование профиля здоровья (имя, год рождения, рост, вес, группа крови);
- создание/удаление напоминаний о пересдаче анализов;
- изменение настроек и скачивание моделей;
- вызовы инструментов ИИ (function calling);
- экспорт мед. карты в PDF;
- ошибки с фронтенда.

Доступна фильтрация по типу действия и полная очистка журнала.

## Профиль здоровья

Приложение работает с одним профилем — для одного человека. В шапке слева
показано имя профиля, кнопка-карандаш открывает редактирование:

- поля профиля: имя, год рождения, рост, вес, группа крови;
- все данные (мед. карта, напоминания, инструменты ИИ) привязаны к этому профилю;
- группа крови сохраняется в нормализованном виде, например `A(II) Rh+`;

## Напоминания о пересдаче анализов

Во вкладке «Моя мед. карта»:

- добавьте напоминание: показатель + интервал в днях (например, «Гемоглобин,
  каждые 30 дней»);
- когда появляется новая запись с этим показателем, напоминание фиксирует
  дату (`last_reported` обновляется автоматически);
- напоминание подсказывает, через сколько дней пора пересдать анализ
  (или отмечает просрочку).

## Telegram-бот

Опциональный бот на long-polling (публичный HTTPS и вебхуки не нужны).
Запускается вместе с сервером, если задан токен и список разрешённых
Telegram ID.

Настройка:

1. Создайте бота у `@BotFather` и получите токен.
2. В меню «Настройки» → «Telegram-бот» вставьте токен и свой Telegram ID
   (свой ID подскажет `@userinfobot`), нажмите «Проверить токен».
3. Отметьте, нужны ли голосовые сообщения и напоминания о пересдаче, сохраните.

Возможности: текст-чат с ИИ (с учётом мед. карты и статей), фото бланка
анализов с распознаванием и подтверждением сохранения в карту (можно
отправить как фото или файлом-изображением — файл не сжимается и
распознаётся точнее), голосовые
сообщения (распознавание — faster-whisper, озвучка ответов — edge-tts,
пакеты из `backend/requirements-voice.txt`) и push-напоминания.

Бот отвечает только пользователям из белого списка. Токен хранится в
`backend/.env` или в папке данных (не попадает в git).

Если из контейнера нет прямого доступа к `api.telegram.org` (запросы
завершаются таймаутом), укажите HTTP/SOCKS-прокси в поле «Прокси для
Telegram» или переменной `TELEGRAM_PROXY` (например,
`socks5h://host:10808`). Если `TELEGRAM_PROXY` не задан, берётся
системный прокси из `HTTPS_PROXY`/`ALL_PROXY` (юнит systemd читает
`/etc/environment`, локальные адреса из `NO_PROXY` идут напрямую).
SOCKS-прокси требует пакет `socksio` (уже в `requirements.txt`).
Частая причина таймаутов — недоступный IPv6 при наличии AAAA-записи у
`api.telegram.org`: по умолчанию бот подключается только по IPv4
(настройка «Подключаться только по IPv4», переменная `TELEGRAM_FORCE_IPV4`).

Если бот отвечает «через раз», проверьте, не опрашивают ли бота два
процесса сразу (`pgrep -af uvicorn`, `systemctl status zelvera`): Telegram
раздаёт сообщения одному из них. Бот держит файл-блокировку
`data/telegram.lock` и второй экземпляр polling не запускает, в логе будет
строка «другой процесс уже опрашивает бота».

## Голосовой ввод

В чате есть кнопка микрофона — распознавание речи через
`webkitSpeechRecognition` (доступно в Chrome/Edge). Распознанный текст
подставляется в поле ввода. Если браузер не поддерживает распознавание,
кнопка скрывается.

## Быстрые подсказки (онбординг)

В начале нового диалога под приветствием показаны чипы с примерами вопросов
(«Покажи мои последние анализы», «Как изменился мой холестерин за последний
месяц?» и т.п.). Клик по чипу отправляет вопрос в чат. Чипы скрываются после
первого сообщения и появляются снова при нажатии «Новый диалог».

## Планы (следующие шаги)

Реализовано:

- MVP с чатом, обработкой фото/PDF/DOCX и личной мед. картой (SQLite);
- база научных статей с RAG-поиском (ChromaDB) и аналитический отчёт;
- заметки (выводы ИИ) с экспортом в PDF;
- профили здоровья и напоминания о пересдаче анализов;
- инструменты ИИ (function calling, только чтение) по данным активного профиля;
- каталог показателей с нормализацией имён, уточнение разбора и справка в чате
  через офлайн-Википедию (с кешем), автотесты pytest в CI;
- графики динамики показателей с коридором нормы и сравнение двух анализов;
- долгосрочный отчёт: годовая сводка показателей и ИИ-оценка здоровья за период;
- Telegram-бот: текст-чат, фото анализов в карту, голосовые сообщения, напоминания;
- аудит действий, логи, десктопное окно (pywebview), сборка Windows (PyInstaller + CI);
- долгая память ассистента L0–L3 (факты, саммари, портрет) локально в SQLite.

Возможные следующие шаги (не приоритетные):

- авто-сводка «Итог за месяц» — LLM-резюме динамики показателей за 30 дней;
- уведомления о напоминаниях при запуске приложения;
- импорт/экспорт данных;
- мобильная адаптация интерфейса.

- Медицинские данные в `data/` исключены из git.
